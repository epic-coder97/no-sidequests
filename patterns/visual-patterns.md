# Visual Pattern Library

Use the smallest visual that reveals the structure of the idea. ASCII is preferred when it can make the relationship immediately visible without adding clutter.

## Cause chain

Use when one event produces another through a short mechanism.

```text
A
↓
B
↓
C
```

Prompt the learner to notice the middle link, not merely the endpoints.

## Transformation

Use when an input is changed by a process.

```text
input -> process -> output
```

Good for computation, biological processes, data pipelines, and manufacturing.

## Flow / rate

Use when the concept concerns amount per unit time.

```text
amount passing
────────────── = rate
time
```

or

```text
more per second -> higher rate
```

## Feedback loop

Use when outputs influence future inputs.

```text
A -> B
↑    ↓
└----C
```

Label the reinforcing or balancing relationship in prose if needed.

## Threshold

Use when behavior changes after a boundary.

```text
low -------- threshold -------- high
                 ↑
           behavior changes
```

## Spectrum

Use when categories are not truly binary.

```text
low ------------------------- high
```

Add only 2–4 meaningful anchors.

## Comparison

Use when two systems share a purpose but differ in mechanism.

```text
X: input -> mechanism A -> outcome
Y: input -> mechanism B -> outcome
```

Use a table only if several parallel dimensions matter.

## Hierarchy

Use when parts are nested.

```text
system
├─ part A
│  ├─ A1
│  └─ A2
└─ part B
```

Do not exceed about three levels in a teaching response.

## Sequence

Use when order matters.

```text
1 -> 2 -> 3 -> 4
```

Annotate only the decision points or transitions that matter.

## Trade-off

Use when improving one dimension tends to worsen another.

```text
more X  <------ trade-off ------>  more Y
```

Then name the variable that determines the preferred balance.

## Part-to-whole

Use when a quantity decomposes into components.

```text
total = A + B + C
```

Keep it symbolic only if the symbols are already meaningful.

## Before / after

Use for interventions, state changes, or transformations.

```text
before -> change -> after
```

## Decision branch

Use when a rule selects among alternatives.

```text
condition?
├─ yes -> A
└─ no  -> B
```

Avoid large decision trees in Focus mode.

## Visual selection test

Before adding a diagram, ask:
1. Does the concept contain a relationship the learner could miss in prose?
2. Can the diagram expose that relationship in fewer elements than another paragraph?
3. Is every label necessary?

If not, use prose instead.
